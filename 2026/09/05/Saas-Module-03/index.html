SaaS Application Architecture: Microservices, APIs and REST

Web’s Client-Server Architecture

Design Pattern Basics

C/S is a type of Design Pattern:

  • a reusable structure, behavior, strategym technique
  • captures a proven solution to a collection of similar problems
  • by separating the things that change from those that stay the same.

C/S Description

SaaS ased on web protocals is widely deployed as C/S Architecture

  • SaaS Client
    • Make one or more request to SaaS Server
    • Ask server for information, allow user to interact with the information
    • Mobile app, Browser, etc.
    • Clients on different platforms can access to the same server.
  • SaaS Server
    • Efficiently serving large numbers of clients simultaneously
    • Typically a collection o computers running multiple different software components.
    • The way for deployment depends on hosting environment and the user scale.
    • Users are unaware of server’s deployment topology.

Motivation For dinstinguishing C/S:

  • allow different type of programs to be specialized to its task.

Alternative for Webapp: Peer-to-peer architecture

BitTorrent: Every participant is both client and server, participant ask information from each other.

Harder to specialize the program to do either job well. But it is useful when the client machines are much cheaper than server machines.

However, since today’s mobile devices are becoming more and more powerful, the C and S are both very complex, but in different ways.

The history of web

1960: Sabre, Airline reservation system

  • Custom FM-based protocal, over leased tel lines

1971: FTP, File Transfer Protocol

  • ASCII-based FTP protocal over TCP/IP

1983: Novell NetWare, allow PCs to share files on a server

  • Custom protocals, PC compatible

1984: POP, Post Office Protocal, allow separation of email clients from servers

  • ASCII-based POP protocal over TCP/IP
  • largely superseded by IMAP

1990: World Wide Web

  • ASCII-based HTTP (Hyper-Text Transfer Protocol) over TCP/IP

Summary

SaaS webapps are examples of client-server architectural pattern.

This is built upon the fundamentally client-server architecture of the Web.

Webapps use open standards, so that anyone can implement royalty-free, compared to some older client-server standards.

p2p (peer to peer) is an alternative, all entities act as both clients and servers.

The primary difference between the clients and servers:

  • client is optimized for user to interact with information
  • server is optimized for serving many clients simultaneously.

HTTP Routes: SaaS Communication

Network Protocol: A set of communication rules on which agents participating in a network agree.

TCP/IP (Transmission Control Protocal)

  • also called Internet Protocal
  • Fundamental protocal linking all computers on Internet.
  • Allows:
    • a pair of agents
    • to exchange ordered sequnces of bytes
    • in both directions
    • simultaneuously
  • This is called Full Duplex
