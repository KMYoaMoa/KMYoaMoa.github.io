How to Learn a New Language

It is important for software engineers to be able to quickly learn and use new languages and frameworks, since they are constantly changing and evolving.

So, we need to learn about how to learn a new language.

Introduction

Things to know about

be familiar with OO Languages

be familiar with basic operations on collections

  • functional programming, lambda
  • filters

be familiar with regular expressions

Concepts to learn

Learning a language and learning a framework simultaneously.

  • understand the new lanuage
  • understand the structure or architectural model the pramework prescribes for applications
  • how the languages features are used to expose that structure

Understand its

  • basic Object-Oriented and encapsulation mechanisms
    • classes, inheritance, commposition
  • its basic imperative mechanics
    • variables, naming conventions, control flow
  • how it manages complexity
    • namespacing, libs, lib and package management

Learning the idioms that make a language unique.

  • mix-ins (duck typing)
  • blocks (anonymous lambdas)

Learning its libraries and how they are managed

  • Ruby libraries are called gems
  • Bundler tool
  • dependencies

Prelude: Learn to learn lang and frameworks

We use the term stack to refer to set of technologies:

  • languages, frameworks, subsystems used in the development

A major part of most stacks is a Framework fo building app, relying on other elements in the stack. We learn stacks, instead of learn a standalone languages.

  • Objective C for iOS
  • React.js
  • Ralis on Ruby

Stacks and frameworks come and go. We need to learn how to learn.

Similarities

Many OO languages are alike because they all:

  • use imperative approach to solve programming problems
  • provide comparable facilities for managing complexity

Technical Vocabulary

Mastering technical vocabulary can help you learn new languages quicker.

They can be divided in to 3 parts.

What’s Different: What idioms or facilities are different from other popular languages? How do they manage libs, the learning of which consumes more time?

  • primitives
    • Variables, types control flow
  • reuse
    • inheritance, interfaces
  • complexity management
    • composition, inheritance, data hiding
  • debugging
  • library usage
    • importing, package/dependency management

App Architecture Implied by Framework:

  • What is the app structure or set of patterns reified by the framework?
  • What are the major “moving parts” of an app?
  • How does their arrangement influence the way we formulate an application’s functionality?

Associate Language’s Features with Framework’s Srturcture:

  • How does the lang help writers by using its mechanisms to expose the framework’s arch and patterns?
    • Ralis relies on convention over config
    • Follow naming rules rather than config file.
    • It is supported by its reflection mechanism

Plan for Learning New Imperative OO Lang

Types and Typing

  • stongly or weakly typed?
  • dynamic (Ruby, JS) or static (C++, Java) typing?
    • dynamic typing: no type declared at compile time, more error chances, but powerful code reuse (mix-ins).

Primitives

  • what are primitive types?
  • rules or conventions for naming? (var, fun, clas, namespace)
  • mechanisms for variable assignment, variable scope, control flow
  • string manipulation, regex and string interpolation

Methods

  • how are they defined / called?
  • how are they named?
  • differentiate class / static methods from instance methods?

Abstraction and Encapsulation

  • how classes are defined, subclassed, composed
  • mechanics for specifying instance methods and variables; static methods and variables, interfaces

Idioms

  • what idioms differentiate the language form others? how are they used?
    • symbols, blocks, iterators, functional programming, etc.

Libraries

  • what facilities does the lang have for managing libraries?
  • how are they named, imported and used?
  • what tools for package management do we have?

Debugging

  • what debugging tools are available?
  • how to use interactive dbugger?
  • how to set breakpoints or watchpoints (data based breakpoints)?

Testing

  • how to create and run automated tests?

Pitfalls

Though the experience in other languages would be helpful in learning new languages, but it is a pitfall trying mapping everything to the language that we are familiar to.

Summary

Most imperative OO languages are philosophically more alike than different.

Developer learns a new language to use a particular framework and stack. Languages will have specific features that make it fit for that frameworkks. Especially the special idioms.

Using a language effectively requires learning how to debug, and use libs, especially managing dependencies.

Pair Programming

Pair Programming is introduced by XP.

The original goal was to improve software quality by having more than one person developing the same code. And it is also a good way to learn new languages and frameworks.

Two developers share one computer, each takes on a different role. A pair would take alternate driving and observing.

  • Driver: enters the code and thinks tactically about how to complete the current task, explaining his or her thoughts out loud as appropriate while typing.
  • Observer / Navigator: reviews each line of code as it is typed in, and acts as a safety net for the driver. Thinks strategically about future problems that will need to be addressed, and makes suggestions to the driver.

Does it Work?

It is a cooperative process, should involve a lot of takling, focuses effort on the task, working together increases the likelihood of following good development practices.

It is effective ONLY IF both collaborators share a common focus throughout the process. If one is silent or away, then it is not pair programming. So if either one cannot keep up, the pair should pause and sync.

It has a side effect of knowledge transferring

  • programming idioms
  • tool trick
  • company processes
  • customer desires, etc.

Studies shows that it can reduce development time and improve software quality.

Summary

pair programming promises higher quality and shorter development time, while cause higher programming costs due to collaboration.

Splits 2 into driver and observer.

Ruby Introduction

Ruby is a Minimalist Language

  • rich libs
  • few mechanisms in language itself

Two principles to read and write Ruby:

  • Everything is an object, every operation is a method call, every call returns a value
  • Ruby has conventional classes, but only instance methods are visible outside the class.
    • All operations to instance vars are through Accessor Methods
    • A var is private if it lacks accessor method.

Types, Typing and Variable Names

Strongly Typed: Objects have types.
Dynamically Typed: Variables don’t have types, they only refer to objects.

Local variables are “barewords”, a single or double @ sign precedes names of instance or class variables.

All variables must begin with lowerase letters. snake_case is strongly preferred over camelCase.

This is because upper camel case is already used for class names, and it is hard to distinguish upper camel cases and lower camel cases.

Other Named Entities

All other named entities must start with Uppercase letters (except for global)

Class names: UpperCamelCase

Different kind of names has different namespaces.

foo, @foo, @@foo, FOO, Foo, $FOO are all distinct.

Boolean Evaluations and Values

Ruby’s true and false are handled with two different classes: TrueClass and FalseClass.

However, there are other things that can be used in a conditional expression, but are not boolean at all. For example: if (e).

To distinguish the boolean values and the non-boolean expressions used as boolean values, we use the trusy and falsy to describe the final boolean results.

That is to say: only false and nil are falsy. Any other thing is trusy, including zero, empty string, etc.

This is quite different with many other languages.

Primitives

nil means an operation that yield no meaningful return value, such as looking up an nonexistent key in a hash. It will either cause falseness or a variable that refers to nothing.

Symbols are some immutable “token” whose value is itself. It is typically used for enumerations. It is not the same as a string, but strings and symbols can be easily converted to each other.

Strings and Regex

Since SaaS will have a large amount of strings to be parsed, mastering regex is a mandatory for programmers and software engineers.

Collections: Array and Has

Collections can combine keys and values of different types.

Hashes are also called arrays or hashmaps in other languages.

Methods

All statemt in between are called the method definition.

All method return a value, if it doesn’t have an explicit return statement, the value of the last expression evaluated is its return value.

Since every Ruby statement results in a value, the return value is always defined.

Classes, Objects and Methods

Since everything in Ruby is a object, which is an instance of some class. Naturally, every operation is performed by calling a method on an object.

The notation obj.meth() calls the meth on the object obj. The object is called receiver and is expected to be able to respond to meth.

Since everything is an object, any result of statment is also an object that can has other methods can be called.

Other Ruby Basic Knowledge

Type Casting

Abstraction and Encapsulation

Ruby supports traditional Inheritance:

A class can inherit from at most one superclass. Ruby doesn’t support multiple inheritance.

All classes inherit from the BasicObject, which is called root class, it has no superclass.

Syntactic Sugar

a+b will be converted to a.+(b). That is to say, the behavior of a+b completely depends on the class of a.

Summary

Everything in Ruby is Objects. Objects have types, while variables does not.

Every operation is a method call, having a receiver that handles the call. It is done through the send function, hidden by syntax sugar.

Every Ruby statement is an expression that has a well-defined value, which could be nil.

Ruby’s classes only support single inheritence, and obey to Uniform Access Principle strictly.

Ruby has comprehensive reflection features.

Ruby supports metaprogramming like attr_accessor, creating code at runtime.

Ruby Idioms

Programming Idiom is a way of doing something that occurs frequently in code written by experienced users of a given programming language.

Poetry Mode and Named Parameters

Poetry Mode allows users to omit many parentheses around the arguments to a method call. Only when the parsing is unambiguous.

When the last argument to a method call is a hash, the curly braces around the hash literal can also be omitted.

In earlier versions of Ruby, hash were often used for Named Parameters or Keyword Arguments.

Blocks

The concept of Blocks in Ruby is different from it is in other languages. A block in Ruby is an anonymous lambda expression.

One of the uses of block is implementing data structure traversal.

The each here is called an internal iterator, which allows Ruby collections to “manage their own traversal”.

Duck Typing

Many collection methods actually does not belong to Array class or any of its superclass. These are based on a powerful mix-in mechanism, which make reusing very convenient.

As long as some class can fulfill some “contract”, a named collection of related methods (called mix-in) can be automatically added to this class.

A module is a Ruby Function for packaging together a group of methods as mix-in. When a statement include ModuleName is written in some class, the instance methods, class methods, variables would be added into that class.

For example, as long as we define the each method, we can include a module called Enumerable in Ruby’s standard library.

Similarly, a class that defines the “spaceship operator”, <=> which returns:

  • $-1$: less than
  • $0$: equal to
  • $1$: greater than

, then the class can include a Comparable module, which would introduce <, <=, >, >=, ==, between? to the class.

However, if the contract is not satisfied, and the module is still included, the there would be a Undefined Method error at runtime.

The term Duck Typing is one popular description of this capability.

If something looks like a duck and quacks like a duck, it might as well be a duck.

Summary

Poetry mode allows omitting parentheses.

Hash arguments were previously used to emulate named parameters, but is discouraged now.

Ruby borrows idea from functional programming and use blocks to describe lambda expressions with context around them, making them closures.

Mix-in takes advantage of duck typing, allows a set of behaviors to be added to any class that satisfies the contract.

Miix-ins require no formal declaration, because Ruby doesn’t have static types.

Gems and Bundler

Gem

A Ruby Library would include a bunch of useful classes covering file and network input/output, time/date, string, collections manipulation, etc.

An external library is packed as a Ruby gem. A gem can argument existing classes and add utility functions, or can contain a whole framework.

Rails, the framwork, is distributed as a gem that depends on other gems.

It is important to manage the dependencies among gems and versions of the required gems.

Bundler

Bundler is the package manager for Ruby. It is a Ruby gem it self.

Bundler requires a Gemfile in the root of working directory. It records the dependencies of the app on particular libraries.

Bundler would read this file and compute lib versions that respects all the constraints, or report that it is impossible.

Then, after bundler installs all the proper versions, it would record them to a Gemfile.lock. Gemfile and Gemfile.lock should be stored as part of the codebase for compatibility.

Versioning

All the gems and Ruby language itself follows the semantic versioning rules.

If some decision that would break API / backword-compatibility is made, it would appear as deprecation warning in a minor version / patch version. And in the next major version, it would be no longer usable.

A best practice for upgrading to a new major version:

  1. Update to the latest version that the major version number is still the same. (2.8.1)
  2. Identiry and address any deprecation warnings.
  3. upgrade to the first release with the new major version. (3.0.0)
  4. upgrade to the latest minor version. (3.1.0)
  5. upgrade to the latest patch version. (3.1.5)

It doesn’t need to be done at once. Developers can gradually update the gems.

Summary

External libraries are distributed as Ruby Gems.

Ruby Gems are managed by Bundler, which is also a Ruby Gem.

Gems and languages follows semantic versioning: major.minor.patch

Upgrade gradually to be prepared for changes.
